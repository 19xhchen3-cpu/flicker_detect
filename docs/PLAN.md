# 频闪检测项目计划

## 项目目标

本项目用于视频频闪检测。目标是在不同视频帧率下，从亮度或强度时序信号中识别频闪，并输出频率、强度等可量化指标。项目保留多种检测方案，允许对同一输入使用不同方案进行检测和比较。

## 现状

- 已有成熟方案和落地项目，本阶段不重新设计或替换检测方向。
- 当前仿真工具为 Python Web 版，已实现参数编辑、即时曲线和卷帘快门条纹仿真。
- 旧 Python 脚本 `sim_tool` 已移除，后续以 `flicker_app` 作为仿真工具入口。
- 开发环境统一使用 conda 虚拟环境 `flicker`。
- 检测算法核心链路已编码并通过单元测试，静态场景分组检测已落地。
- 前端工作台已支持视频上传、预处理、检测叠加、历史亮度多块对比、悬停诊断和手动重算。
- 前端已合并为单一工作台，通过导航栏切换“视频检测”和“频闪仿真”。
- 当前范围：只做 30fps 检测；不实现移动端 v3（Goertzel 频域方案，见
  `docs/flicker_v3_implementation.md`），其余 fps 的参数组合暂不补齐。

## 设计构思

- 多方案并存：保留现有多种检测方案，新增方案时不破坏已有方案，不预先限定单一算法。
- 统一边界：视频读取、帧率处理、亮度或强度信号提取、频闪分析、结果输出之间保持清晰接口，便于替换和扩展。
- 帧率适配：不同帧率视频使用一致的时序基准，频率指标统一使用 Hz，避免帧序号和时间戳混用。
- 结果可解释：除检测结论外，保留中间信号、分析参数和置信度信息，便于验证与复盘。
- 前端约束：使用 Python 标准库 HTTP 服务和原生 HTML/Canvas 实现参数编辑器与绘图。
- 行级仿真约束：4K 画面按 2160 行建模，单帧内行曝光开始时间按 `y/2160 × 帧周期` 均匀错开，用于模拟卷帘快门产生的帧内频闪条纹。

## 检测算法设计（静态场景已落地）

### 频率定义

- 检测频率 `fd`：光源驱动频率，例如 50 Hz 市电。
- 光强频率 `F`：驱动频率产生的实际亮度频闪，当前模型取 `F = 2 × fd`，例如 100 Hz。
- 视在频率 `fa`：逐帧采样后实际能观察到的折叠频率。
- 视在周期 `P`：`P = fps / fa`；例如 30 fps、100 Hz 光强频闪得到 `fa = 10 Hz`、`P = 3`。

### 已确认的检测流程

- 先复现静态场景下的分组检测，运动场景处理后续单独实现。
- 输入为帧序列和 fps；时间戳用于统一时间基准，避免只依赖帧序号。
- 画面按块切分，块亮度使用块内平均亮度。
- 按 fps 和目标驱动频率预先建立分组规则，只检测预设目标频率。
- `group_size` 直接配置；编码前通过二维查找表按 fps 和目标频率确定分组参数，检测时选中一个特定目标频率。
- 对每个目标频率计算 `F`、`fa`、`P`。
- 历史窗口统计帧数为 `P + 1`，通过相邻帧亮度差分形成完整周期；相邻窗口首尾共享一帧。
- 对历史亮度曲线进行分组匹配，匹配成功即认为检测到目标频闪；置信度设计后续补充。
- 历史曲线按预期视在周期切分为多个周期组，每个块独立判定，不使用相邻块的连通性、形状或空间关系。
- 周期组需同时满足四项特征：
  - 相邻帧亮度变化具有足够振幅。
  - 一个周期首尾基本闭合，不是持续变亮或持续变暗。
  - 多个周期组重复出现相同的亮度升降符号模式。
  - 相同相位位置在不同周期中的振幅保持稳定。
- 高于 Nyquist 的频率理论上可从时间视在频率和空间卷帘快门条纹重建，但当前实际算法不依赖数条纹；条纹计数仅作为理论可行性依据。

### 输入状态结构

- `state.history`：按时间保存的逐块亮度历史，逻辑顺序为最旧帧到最新帧；物理形状为 `[frame, block]`，物理存储使用环形缓存，容量复用 `min_frames`。
- `state.valid_count`：当前历史缓存中的有效帧数。
- `state.write_index`：环形数组指针；新帧从头部进入，旧帧从尾部退出。压入后计算时指向下一位置，压入前计算时指向当前写入位置；实现将统一采用压入后指向下一位置。
- `state.block_count`：需要独立执行判定的块数量，每块检测互不依赖。
- 算法参数：fps、目标驱动频率、分块参数、历史缓存容量、四项特征阈值等。
- 无效帧或丢帧时，`valid_count` 和 `write_index` 重置，检测重建缓存后计算。
- 后端参数表覆盖需要检测的 fps 和频率组合；前端下拉只展示 `group_size_for()` 可形成整数视在周期的组合，并从参数表同步阈值。

### 算法参数定义

| 参数 | 含义 |
| --- | --- |
| `min_frames` | 启动检测所需的最少有效历史帧数，控制冷启动长度和最早输出时机。 |
| `history` | 历史缓存容量和诊断滑动窗口大小，复用 `min_frames`。 |
| `group_size` | 一个周期组包含的帧数，决定预期混频周期、组内差分位置和相位对齐。 |
| `min_match_groups` | 主导模式必须超过的最少匹配组数，控制周期证据的绝对数量要求。 |
| `min_group_amp_ratio` | 最低有效振幅占满量程的比例，用于控制振幅门槛。 |
| `min_amp_pos_ratio` | 周期组内必须通过振幅门的位置比例，控制对波形平台位置的容忍程度。 |
| `same_pattern_ratio` | 主导符号模式所需达到的最低复现比例，控制周期模式的一致性要求。 |
| `slope_max` | 一个周期首尾允许存在的最大平均变化率，用于剔除持续变亮、持续变暗和曝光趋势。 |
| `max_group_amp_cv` | 不同周期之间允许的最大振幅方差系数，控制周期振幅稳定性要求。 |
| `cols` | 画面分块的列数。 |
| `rows` | 画面分块的行数。 |
| `y_max_bit` | 输入亮度位深；后端换算满量程 `y_max = 2^bit - 1`，例如 14bit 即 16383。 |

- 当前默认值已填写：`min_frames=30`、`min_match_groups=2`、`min_group_amp_ratio=0.001`、`min_amp_pos_ratio=0.5`、`same_pattern_ratio=0.8`、`slope_max=10.0`、`max_group_amp_cv=0.4`、`y_max_bit=14`、分块 `16×12`。
- `group_size` 仍只有 30fps 的 50/100/125/200/500 Hz 组合填写为 4，其余组合为 0；前端下拉按 `group_size_for()` 可整数分组结果展示候选挡位。

### 参数关系与约束

- `group_stride` 应与真实混频周期一致，否则符号模式会因相位漂移而无法复现。
- `group_count` 必须大于 `min_match_groups`，否则算法不可能形成足够的主导模式组。
- K-of-N 中的 `K` 由 `group_size` 和 `min_amp_pos_ratio` 共同决定；位置数量较少时，`K` 可能退化为所有位置都必须通过。
- `min_group_amp_ratio` 同时参与单次差分振幅门和 CV 位置过滤，修改时会同时影响两种不同统计量。
- `slope_max` 应小于通过振幅门的单调变化组所能形成的最低斜率，否则趋势型信号可能通过周期闭合检查。
- 历史窗口越长，可用周期组越多，但非整数周期造成的累积相位漂移也会增大，模式复现比例需要与之协调。

### 设计边界与已知问题

- 算法逐块独立判定，不利用空间连续性，因此不会判断命中块是否形成真实频闪区域。
- 符号模式采用完全相等比较，低振幅位置的符号仍可能受到噪声影响。
- 多个符号模式类大小并列时，当前实现按遍历顺序保留最先出现的模式，缺少物理意义的裁决规则。
- CV 使用总体方差，小样本情况下可能低估实际振幅波动。
- `min_group_amp_ratio` 同时承担两类统计量的门槛，后续可考虑拆分为独立参数。
- 参数组合缺少完整合法性校验，错误配置可能导致静默零检出或判定条件退化。
- 算法依赖预先确定的周期分组参数，本函数本身不负责测量实际频率。
- 在遇到既定频率的亮暗场景变化时仍可能发生误检；该边界需要作为检测标准的一部分明确记录。
- 当前缓存实现为 `list + shift`，尚未使用计划中的环形缓存；结果语义一致，后续可替换为环形缓冲。

### 周期分组派生量

- `group_size`：每个周期组包含的帧数，等于 `P + 1`。
- `group_stride`：`group_size - 1`，即相邻周期组起点之间的帧数，与当前采样条件下的混频周期一致。
- `position_count`：`group_size - 1`，一个周期组内相邻帧差分的位置数量。
- `group_count`：`floor((valid_count - 1) / group_stride)`，当前历史下可形成的完整周期组数。
- `used_frames`：`group_size + (group_count - 1) × group_stride`，本次实际使用的帧数。
- `drop_count`：`valid_count - used_frames`，本次计算从最旧端舍弃的帧数，使分组尽量对齐最新历史。
- 相邻周期组共享边界帧，起点之间恰好相隔一个预定周期。

### 单块特征构建

- 每个块独立遍历所有周期组和组内位置，计算相邻帧亮度差分。
- `diff[g, p] = history[t + 1] - history[t]`
- `amp[g, p] = abs(diff[g, p])`
- `sign[g, p] = sign(diff[g, p])`
- `amp_matrix` 描述各周期位置的亮度变化强度。
- `sign_matrix` 描述各周期位置是亮度上升、下降还是不变。
- 已确认：矩阵维度采用 `[group_count, position_count]`；`sign == 0` 参与后续符号匹配，零容差为绝对亮度值。

### K-of-N 振幅门

- `min_group_amp = y_max × min_group_amp_ratio`
- `K = ceil(position_count × min_amp_pos_ratio)`
- 一个周期组中至少需要 `K` 个位置的振幅超过 `min_group_amp`，即 `count >= K`，该组才被判定为有效变化。
- `K-of-N` 允许周期波形中存在少量平台位置，避免单个近零差分否决整个真实频闪周期。
- 已确认：`y_max` 为输入亮度满量程值，`min_group_amp` 为绝对亮度差门槛；振幅通过条件为 `amp > min_group_amp`。
- 已确认：K-of-N 的计数量通过条件为 `count >= K`；它不同于振幅本身的严格 `>` 比较。
- 已确认：`min_amp_pos_ratio = 0` 时禁用 K-of-N 门，所有组直接通过。
- 已确认：当前默认值为 `min_group_amp_ratio=0.001`、`min_amp_pos_ratio=0.5`。

### 周期闭合斜率门

- `slope = (history[first + group_stride] - history[first]) / group_stride`
- 周期震荡在相同相位处应回到接近的亮度。
- 若 `slope` 超过允许范围，则该组更接近持续变亮或持续变暗，或受曝光趋势影响，算法将其剔除。
- 允许范围由 `slope_max` 控制；剔除条件为 `abs(slope) > slope_max`。
- 已确认：`first` 使用丢弃最旧帧后的逻辑索引；`slope_max` 单位为亮度/帧。
- 已确认：`slope_max = 0` 时禁用闭合斜率门，但 K-of-N 振幅门仍然生效。

### 主导符号模式匹配

- 算法依次把每个幅度有效组作为候选模式，在全部幅度有效组中查找符号序列完全相同的组。
- 选择成员数量最多的符号模式等价类作为主导模式候选。
- 符号模式相同满足自反、对称、传递关系，因此幅度有效组可划分为若干互不相交的等价类。
- 当前实现使用 `class_id[group]` 保存每个组所属等价类的代表组；候选组完成比较后立即为所有匹配组写入同一 `class_id`。
- 外层遍历遇到已归类的组直接跳过，避免重复把同一等价类作为候选进行搜索。
- 最大等价类达到模式复现比例要求后，才被标记为主导模式。
- 主导模式对应组数记为 `flip_count`，且必须超过最少匹配组数。
- 门槛通过后，直接按 `class_id[group] == best_candidate` 设置组级匹配标志，不再重新扫描 `sign_matrix` 比较每个位置。
- 优化必须保持严格大于比较，确保检测结果不变。
- 复杂度：多数组属于相同模式时接近 `O(G × P)`；每个组都不同的极端情况下最坏为 `O(G^2 × P)`。后续可把符号序列编码后用哈希计数降到 `O(G × P)`。
- `flip_count` 理解为主导等价类中的组数；复现比例阈值由 `same_pattern_ratio` 控制，最少匹配组数由 `min_match_groups` 控制。
- 已确认：候选组需同时通过 K-of-N 和闭合斜率门；`same_pattern_ratio` 的分母为全部有效组；`flip_count > min_match_groups`。
- `sign == 0` 参与符号等价类匹配；振幅在 `±1e-4f` 内视为符号 0；`1e-4f` 为绝对亮度容差。

### 跨周期振幅 CV 门

- 对主导模式中的周期组，按相位位置分别收集振幅：
  - `mean_amp[p] = mean(amp[g, p])`
  - `CV[p] = sqrt(var(amp[g, p])) / mean_amp[p]`，即总体标准差除以均值
  - `max_pos_cv = max(CV[p])`
- 平均振幅未达到最低门槛的位置不参加方差聚合，避免平台位置和量化噪声主导结果。
- 算法取所有有效相位位置中的最大方差作为最严格的稳定性指标。
- 若没有任何位置能参加统计，则该块按不可判定处理。
- 参与统计的最低平均振幅门槛为 `min_group_amp`，通过阈值为 `max_group_amp_cv`；当前使用总体标准差。
- 已确认：位置过滤条件为 `mean_amp[p] > min_group_amp`；当前固定使用总体标准差。
- 已确认：`max_pos_cv > max_group_amp_cv` 时拒绝该块。
- 已确认：`max_group_amp_cv = 0` 时禁用 CV 门；无有效位置时诊断量输出 `NaN`，避免把“不可判定”误读为零方差。

### 块最终判定

- 一个块只有同时满足以下条件才会被标记为频闪：
  - 主导模式包含足够多的周期组。
  - 主导模式组数超过最少匹配组数。
  - 有效相位位置的最大振幅方差不超过允许范围。
- 判定通过后，设置对应的 `block_flags` 并累加 `flicker_block_num`。
- 当前映射为 `flip_count / 有效组数 > same_pattern_ratio`、`flip_count > min_match_groups`、`max_pos_cv > max_group_amp_cv` 时拒绝。
- 已确认：不可判定与无频闪在输出上一致，`block_flags` 只有 0/1，`flicker_block_num` 不累加。

### 输出状态结构

- `block_flags`：每个块的频闪判定标志。
- `flicker_block_num`：本次计算中被判定为频闪的块数量。
- `mean_abs_diff`：主导模式中有效相位位置的平均振幅诊断量。
- `diff_cv`：主导模式各有效相位位置的最大振幅归一化方差。
- `sign_flip_ratio`：主导符号模式组数占全部有效组的比例。
- `avg_ratio_diff`：按滑动窗口原始亮度最大值与最小值比值的平均值，用于诊断。
- `avg_delta_diff`：按滑动窗口原始亮度极差的平均值，用于诊断。
- 已确认：输出状态不包含目标驱动频率或视在频率。
- 已确认：诊断量按块输出，每个块各输出一组。
- `avg_ratio_diff = mean(max(raw_window) / min(raw_window))`
- `avg_delta_diff = mean(max(raw_window) - min(raw_window))`
- 窗口内最大值、最小值均为原始帧亮度；滑动窗口长度复用 `history`，即 `min_frames`。

### 问题确认记录

- `group_size` 直接配置；编码前用二维查找表按频率与 fps 查分组参数，检测时选定一个目标频率。
- `min_frames` 与历史缓存容量无直接关系，但一般保持一致。
- 无效帧或丢帧时，`valid_count` 和 `write_index` 重置，检测重建缓存后计算。
- `amp_matrix` / `sign_matrix` 使用 `[group, position]`。
- `sign == 0` 参与符号等价类匹配；振幅在 `±1e-4f` 内视为 0，`1e-4f` 为绝对亮度容差。
- 主导符号匹配候选组需同时通过 K-of-N 和闭合斜率门；`same_pattern_ratio` 分母为全部有效组。
- CV 位置过滤以 `mean_amp[p] > min_group_amp` 为准，当前使用总体标准差。
- 不可判定与无频闪输出相同：`block_flags` 只有 0/1，`flicker_block_num` 不累加。
- 输出状态不包含目标驱动频率或视在频率。
- 振幅门使用 `amp > min_group_amp`；闭合门剔除 `abs(slope) > slope_max`；CV 门拒绝 `max_pos_cv > max_group_amp_cv`；主导模式要求 `flip_count > min_match_groups`。
- K-of-N 的计数量通过条件为 `count >= K`，与严格 `>` 比较的阈值不同。
- `min_amp_pos_ratio = 0` 禁用 K-of-N，`slope_max = 0` 禁用闭合斜率门；主导模式参数为 0 时也视为禁用对应约束。
- `max_group_amp_cv = 0` 禁用 CV 门；CV 无有效位置时按不可判定处理，诊断量输出 `NaN`。
- `write_index` 为环形数组指针；新帧头部进入、旧帧尾部退出；压入后计算指向下一位置，压入前计算指向当前位置。
- 配置表只包含需要检测的 fps 模式和对应频闪频率，不在表中的组合不检测。
- `sign == 0` 的 `1e-4f` 为绝对亮度容差。
- 诊断量按块输出，每个块各输出一组。
- `fa = 0` 等有问题的频率/帧率组合通过配置表规避，算法不检测这些组合。
- `avg_ratio_diff` 和 `avg_delta_diff` 按原始帧亮度的滑动窗口计算：比值取窗口最大值/最小值，极差取窗口最大值减最小值。
- `slope_max = 0` 只禁用闭合斜率门，K-of-N 振幅门仍然生效；Python 与前端已统一该行为。
- 提前退出主导模式计数循环不可行：`best_size` 需为最终值（供 `flip_count` 诊断与 CV 成员收集使用）；安全剪枝为 `min_match_groups > 0` 且 `valid_group_count <= min_match_groups` 时整块跳过计数与 CV，阈值越高省得越多。
- `min_match_groups` 与 `same_pattern_ratio` 约束同一量 `best_size`，等效 `best_size > max(min_match_groups, ratio × valid_count)`；有效组多时比例门槛主导，组少时数量门槛主导，只调一个会被另一个覆盖。
- 计算时间优先优化顺序已调整为：安全剪枝 -> CV 单趟统计（Welford）-> 流式增量检测 -> C++ 数值替换；符号编码保留条件短循环，编码合并仅在 profiling 证明第二遍循环为瓶颈后实施。

### 前置数据转换模块计划

- 目标：读取指定地址的视频，灰度化，按参数表中的 `cols` / `rows` 分块压缩，增加可调 gamma 提亮，输出逐帧块亮度供检测缓存使用。
- 输入：视频地址、fps/时间基准、`cols`、`rows`、gamma 提亮力度。
- 输出：每帧包含 `frame_id` 和一个块亮度数组，块亮度建议按行优先展开为 `[rows * cols]`，与 `state.history` 的 `[frame, block]` 对齐。
- `frame_id` 作为算法使用的帧索引，后续周期分组按 `frame_id` 对齐，而不是依赖环形缓存的物理位置。
- `frame_id` 由前置模块按视频读取顺序自动分配，建议从 0 开始递增。
- 处理流程：
  1. 使用 `cv2.VideoCapture` 打开视频并读取 fps、帧数、宽高等元数据。
  2. 将 BGR 帧转换为灰度图。
  3. 执行 gamma 提亮：`output = y_max × (input / y_max) ^ gamma`，`gamma < 1` 时提亮。
  4. 按 `rows × cols` 网格分块，计算每个块的平均亮度。
  5. 输出块亮度数组和视频元数据。
- 依赖：需要引入 `opencv-python` 并写入 `requirements.txt`。
- 当前实现口径：
  - gamma 为全局管道参数，默认 1.0，并在分块平均之前应用。
  - 分块压缩使用 `cv2.INTER_AREA` 区域平均。
  - 输出块数组使用 `[rows × cols]` 行优先。
  - `frame_id` 由前置模块从 0 自动递增。

- 当前实现状态：
  - 已实现 `flicker_detect/preprocess.py`。
  - 已实现 `app/` 视频上传、流式转换和进度展示页面。
  - 指定测试视频 1092 帧完整转换通过，耗时约 204s，有效速度约 5.35 fps。

### 前置数据转换模块风险与缺口

- 位深未做自动探测：当前固定 14bit/16383，参数表以 `y_max_bit=14` 配置；8/10/12/16 bit 自动识别和缩放仍未实现。
- 时间基准不完整：仅输出 `frame_id` 不足以处理变帧率和丢帧；建议同时输出真实时间戳，并在检测端使用 `frame_id` 做分组、时间戳做时间基准校验。
- 读取失败语义未定义：`cv2.read()` 返回失败、视频损坏、编码不支持或中途断流时，模块应明确是跳过、中止还是标记无效帧，不能静默破坏帧序列。
- 分块边界未定义：当宽高不能被 `cols` / `rows` 整除时，边缘块的大小如何分配、是否裁剪或补齐，需要明确。
- 参数校验不足：`cols`、`rows`、gamma、视频路径都必须校验；`cols × rows` 应与检测参数的 `block_count` 一致。
- gamma 边界未定义：需要明确 gamma 取值范围、0 值处理、输入越界裁剪，以及 `gamma = 1` 时是否严格保持原亮度。
- 内存模型未定义：建议使用逐帧生成器流式输出，避免一次把整段视频读入内存；`VideoCapture` 必须在结束时释放。
- 元数据契约未定义：建议返回 `fps`、帧数、宽高、位深、时间基准、`cols`、`rows`、gamma 等元数据，供检测模块校验和记录。
- 自动测试缺口：需要覆盖 8/10/12/14/16 bit、非整除分块、gamma 单调性、`frame_id` 连续性、空视频、损坏视频和错误路径。
