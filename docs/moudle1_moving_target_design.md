# moudle1 移动目标频闪检测设计（待排期）

> 状态：**设计草案，尚未实施**。本文记录"画面中移动目标频闪检测"的需求、
> 现状问题、能力边界与推荐技术路线，供后续排期实现时直接取用。
> 相关文档：[pure_logic_detector_design.md](./pure_logic_detector_design.md)。

## 1. 需求背景

未来需要对画面中**移动的目标**做频闪检测：发生频闪的光源不一定在画面中
静止不动，可能因光源自身运动、载具移动或相机摇移而持续改变相对画面位置。
因此运动因素必须纳入检测设计，不能只针对静止目标。

当前 `flicker_detect/moudle1.py` 的流式增量实现（提交 `86ed499`）采用
**相位锁定 + 跳帧**：分组相位锚定在首个帧号上，第 k 组覆盖绝对帧
`[phase_base + k*P, phase_base + k*P + P]`，只在组完成帧（
`(frame_id - phase_base) % P == 0`）计算新组特征并重扫判定，中间帧复用
上一结论。该实现针对静止/稳定周期信号做了新旧对照验证，性能为旧全量链路的
约 5.7 倍，但**对移动/瞬变目标存在系统性回归**（见第 2 节）。

## 2. 现状问题：移动/瞬变目标的检出回归

### 2.1 机制差异

- **旧全量实现**（`detect_window`/`HistoryBuffer`，已删除）：分组永远对齐
  **最新帧**（`group_starts = [drop_count + g*P]`，最后一组末尾即当前帧）。
  因此任意结束时刻的 P+1 帧完整周期突发，在它结束的那一帧做检测时，恰好被
  **一个完整组**捕获。
- **流式增量实现**：分组相位固定，突发若不落在相位边界，会被**劈进相邻两个
  组**，每组都混入背景帧——闭合斜率、K-of-N 门大概率直接判废；即使不废，
  两个半截组的符号模式不同，也无法形成主导。
- 结论刷新节奏：流式只在组完成帧出新结论，中间帧返回缓存，结论（含
  `window_end`）最多滞后 P-1=2 帧，等于用 2 帧前的画面出结果。

### 2.2 已验证的对照结果

用 30fps/50Hz（B=192、H=30、group_size=4、P=3、G=9）、合成周期信号实测
（补偿口径：`min_match_groups=0`、`same_pattern_ratio=0`，其余门不变）：

| 场景 | 旧方案（对齐最新帧） | 流式增量 |
| --- | --- | --- |
| 突发在帧 26..29（不落在相位边界） | 帧 29 检出（1 个有效组，比例 1.00） | 帧 27/30/33 全部未检出 |
| 突发在帧 27..30（恰好落在相位边界） | 帧 30 检出 | 帧 30 检出 |
| 慢速移动：目标同块停留 24 帧（6 组），默认阈值 | 帧 27 检出（7 个有效组） | 帧 27 检出 |

结论：流式不是"不能检突发"，而是"只能检恰好对齐相位边界的突发"；对静止/
慢速目标两者完全一致（这也是现有新旧对照测试通过的原因——对照用例均为稳态
信号，未覆盖瞬变/移动场景）。

## 3. 网格检测的能力边界

现有算法本质是"每个块独立分析其亮度时间序列"，因此一个移动光源能否被检出，
取决于它在**同一个块里停留多久**（30fps、P=3、一个周期组 = 4 帧）：

| 运动速度 | 块内停留 | 现有流式（单相位+跳帧） | 网格法理论极限 |
| --- | --- | --- | --- |
| 静止 / 亚块抖动（手持、微震） | ≥ 19 帧（默认阈值需 6 组） | 可检出 | 可检出 |
| 慢速移动（步行、缓慢摇镜） | 约 4~18 帧（1~5 组） | 相位靠运气 | 全相位 + 降阈值后可检出 |
| 中速移动（约 1 组/块） | 约 4 帧 | 劈裂漏检 | 全相位后勉强可达 |
| 高速移动（< 4 帧/块） | 不足 1 组 | 不可检出 | 不可检出，必须沿轨迹采样 |

实际场景中，步行或缓慢摇镜的物体通常每块停留 0.5 秒以上（约 15 帧），属于
第二行——网格法加全相位对齐和补偿阈值即可覆盖。需要换架构的是高速场景
（快速扫过画面、车辆等），此时每个块内只有 1~2 个采样点，任何逐块网格法都
无法检出，必须做轨迹采样（见第 5 节）。

## 4. 推荐路线 A：P 相位旋转 + 并集输出

不改变网格、不丢弃增量计算，把"锁定单一相位"换成"同时维护 P=3 个相位"。

### 4.1 原理

- 每个相位 a（组起点 ≡ a mod 3）独立维护 G 组特征；相位 a 的第 k 组覆盖
  绝对帧 `[a + 3k, a + 3k + 3]`。
- **每帧恰好有一个相位完成一组**（a = 帧号 mod 3），即旧方案"对齐最新帧"
  的那一组。因此每帧只需：写帧 + 计算一个新组特征 + 刷新**该相位**的结论；
  其余两个相位的组集合没有变化，结论直接复用缓存。
- 输出取三个相位结论的**并集**：静止目标各相位结论一致（新旧对照已验证
  结论一致性）；移动/瞬变目标总有一个相位能在突发结束帧完整捕获它。
- 逐块层面的瞬变命中（通常只持续 1 帧结论）由上层补偿/轨迹模块按时间聚合，
  形成稳定的目标级结论。

### 4.2 成本

以实测的组完成帧成本（约 6.7 ms）推算：

| 方案 | 平均每帧成本 | 说明 |
| --- | ---: | --- |
| 旧全量重算 | ~13 ms | 每帧全窗重算 |
| 当前流式（单相位+跳帧） | ~2.0 ms | 1/3 帧执行判定 |
| P 相位旋转（每帧一次判定） | ~6.5~7 ms | 每帧一个相位完成一组 |
| P 相位 + 4.3/4.4 轻量优化 | 预计 4~5 ms | 去 `float()` + Welford 单趟 CV |

可选**运动触发开关**：帧间块差异低于阈值时走单相位快路径（保持 ~2 ms），
检测到运动再切全相位——保留静止场景已验证的性能收益，运动时自动降速换能力。

### 4.3 对现有代码的影响

- `create_incremental_state()`：`group_amp`/`group_pattern` 扩成 P 份；
  新增 P 份结论缓存与并集输出。
- `detect_window_incremental()`：每帧计算"当前相位的新组"（现只在
  `rel % P == 0` 时计算），并刷新当前相位结论。
- API 语义变化：结论不再每 3 帧缓存复用，`window_start`/`window_end`
  每帧推进（回到旧方案节奏），`tests/test_api.py` 等期望值需同步更新。
- 保持单函数 + 纯 dict + 显式循环 + 固定数组，C++ 映射结构不变（P 份
  相位状态对应 C++ 成员数组，每帧入口仍为
  `detect_window_incremental(State& state, const float* blocks, int frame_id)`）。

## 5. 推荐路线 B：轨迹采样（高速场景，独立模块）

目标跨块速度超过约 1 块/4 帧时，正确做法是：跟踪目标位置 → 沿运动轨迹
采样亮度 → 形成一条**虚拟时间序列** → 复用同一套组/符号模式/振幅 CV 判定。

- 需要跟踪层：块级质心跟踪或下游目标跟踪 API，输出目标每帧位置。
- 需要固定容量的目标槽位（每条轨迹一条虚拟序列），在 C++ 里对应固定数组。
- 预估 200~400 行，属于**新模块**，不建议与路线 A 的网格改造混做。
- 依赖关系：路线 A 是网格层的基础能力补齐；路线 B 在其之上做轨迹级聚合，
  两者可叠加。

## 6. moudle1 改动量测算（路线 A）

| 改动点 | 内容 | 预估行数 |
| --- | --- | --- |
| state | `group_amp`/`group_pattern` 扩成 P 份；P 份结论缓存 + 并集 | 20~30 |
| 特征计算 | 每帧算"当前相位的新组" | 15~25 |
| 判定 | 每帧刷新当前相位结论；并集输出 | 40~60 |
| 测试 | 移动/瞬变用例（突发在不同相位、不同速度） | 60~100 |

合计约 140~220 行，以当前 `moudle1.py`（329 行，三个纯函数）为基准。

## 7. 测试建议

现有新旧对照测试只覆盖静止/稳态信号，无法暴露本回归。后续实现必须补充：

1. **瞬变突发用例**：4 帧完整周期突发分别落在不同相位边界（如帧 26..29、
   27..30），验证并集输出在两种情况下都能检出；
2. **慢速移动用例**：目标同块停留 12~24 帧后迁移到相邻块，验证跨块检出
   与轨迹聚合；
3. **高速移动用例（路线 B）**：轨迹采样虚拟序列与逐块网格结果对比；
4. 保持原有 fedetect 对照、剪枝、CV、就绪/重置等回归用例。
