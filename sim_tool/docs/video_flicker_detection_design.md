# 视频频闪检测算法设计文档（神经网络方案）

> **目标**：设计一个**以神经网络为主干**的电脑端视频频闪检测算法，能够检测不同帧率视频中的频闪位置及频闪频率。

---

## 1. 背景与问题定义

### 1.1 什么是频闪（Flicker）

视频频闪指画面亮度以一定频率周期性波动的现象。常见成因包括：

- **光源频闪**：交流电驱动的光源（如 50Hz/60Hz 荧光灯、LED）与摄像机快门/帧率之间的 beats 效应
- **显示器刷新率不匹配**：录制屏幕时帧率与显示器刷新率不同步
- **拍摄设备问题**：自动曝光/白平衡频繁调整
- **传输/编码问题**：视频编码中亮度分量异常波动

### 1.2 检测目标

| 指标 | 说明 |
|------|------|
| **频闪位置** | 频闪在画面中的空间区域，以分割掩码输出 |
| **频闪频率** | 真实频闪频率（Hz），如 100Hz、800Hz |
| **不同帧率适应** | 支持 24/30/48/50/60/100/120/240fps |
| **频率范围** | 100Hz ~ 1000Hz（对应光源 50Hz ~ 500Hz ×2） |
| **解混叠能力** | 利用卷帘快门产生的空间条纹信息，还原真实频率 |
| **拍摄设备** | 原生 8K 传感器，视频为 1080p / 4K 输出 |
| **硬件环境** | RTX 4060 Ti 8GB |

### 1.3 为什么用神经网络？

传统方法（FFT/Welch）的局限：

| 问题 | 传统方法 | 神经网络方案 |
|------|---------|-------------|
| **运动干扰** | 需额外运动掩码模块，且阈值为经验值 | 端到端学习运动与频闪的区分特征 |
| **弱频闪** | 弱频闪被噪声淹没 | 可学习弱信号模式，鲁棒性更强 |
| **空间定位** | 依赖分块 + 连通域，边界粗糙 | 像素级分割，边界更精确 |
| **多帧率适应** | 需手动调整参数 | 条件注入帧率信息，网络自适应 |
| **混叠解算** | 需先验知识 + 手工反推 | 利用卷帘快门条纹，端到端学习 |

## 3. 已确定的架构决策

### 决策 ①：帧率通过 FiLM 条件向量注入

帧率不用于重采样，而是作为条件信息注入网络。

```
fps (scalar) → [MLP] → γ, β → γ·feature + β (FiLM)
```

- 应用于网络中的关键特征层
- 训练时允许 fps 加 5% 随机扰动增强鲁棒性
- 网络隐式学习 fps 与采样频谱的关系

### 决策 ②：窗口参数

| 参数 | 值 | 依据 |
|------|----|------|
| **网络输入窗口** | **1.5 秒** | 覆盖最低 2Hz 表观频率 ≥3 个周期 |
| **滑动步长** | **0.5 秒** | 67% 重叠，保证结果平滑 |
| **高帧率时间降采样** | conv1 时间维 stride 自适应：30fps→1, 60fps→2, 120fps→4, 240fps→8 | 统一 conv1 后 T'，保证显存可控 |

各帧率对应的帧数：

| fps | 1.5s 窗口帧数 | conv1 时间 stride | conv1 后 T' |
|-----|-------------|-----------------|------------|
| 24 | 36 | 1 | 36 |
| 30 | 45 | 1 | 45 |
| 48 | 72 | 2 | 36 |
| 50 | 75 | 2 | 37 |
| 60 | 90 | 2 | 45 |
| 100 | 150 | 4 | 37 |
| 120 | 180 | 4 | 45 |
| 240 | 360 | 8 | 45 |

### 决策 ③：输入与输出分辨率

| 参数 | 值 | 说明 |
|------|----|------|
| **推理输入分辨率** | **48×64** | 高度 48px，宽度 64px，12×16 分割网格 |
| **训练时分辨率增强** | RandomResize 48×64 ~ 96×128 | 数据增强，让网络适应多尺度输入 |
| **分割输出** | **12×16 网格** | 每个 grid cell 判断频闪的有无和频率 |
| **压缩策略** | 原生 4K/1080p → bicubic 缩放到 48×64 | 45:1 垂直压缩，条纹对比度在最坏情况（30fps×1000Hz）下保留约 34% |

> **关于分辨率的讨论**：48×64 在所有 (fps, 频率) 组合下的条纹信息经过空间混叠后仍然保留不同模式，足以区分各频率类别。训练时用 96×128 做随机缩放增强，可使网络更好地泛化条纹特征。

### 决策 ④：端到端学习真实频率，利用卷帘快门条纹解混叠

核心原理：

```
卷帘快门逐行曝光 → 每帧内各行曝光相位不同 → 出现明暗条纹

帧内空间条纹数  → 隐含 k (混叠阶数)
帧间亮度变化    → 隐含 f (表观频率)
端到端组合       → fs = k·fps + f
```

**不需要**：
- ❌ 不需要显式输出 k
- ❌ 不需要知道 T_readout / 传感器规格
- ❌ 不需要预先知道焦距/快门参数

网络直接从 (帧序列, fps) 映射到真实频率 fs。

### 决策 ⑤：数据与标注

| 参数 | 值 |
|------|----|
| **数据来源** | 真实拍摄视频（无合成数据） |
| **帧率挡位** | 24fps, 30fps, 48fps, 50fps, 60fps, 100fps, 120fps, 240fps |
| **频闪频率** | 100Hz, 120Hz, 160Hz, 200Hz, 238Hz, 240Hz, 250Hz, 260Hz, 360Hz, 800Hz, 1000Hz |
| **频率标注** | 人工标注，严格正确 |
| **频率范围** | 100Hz ~ 1000Hz |
| **标注格式** | JSON（时间范围 + 空间多边形/掩码 + 频率值） |
| **标注切分长度** | **3~6 秒**（标注人员在该粒度上标注频闪范围，后续自动切 1.5s 窗口） |
| **标注流程** | 标注员查看视频 → 标记频闪时间段 → 在某一帧上画区域 → 填入频率 → 自动生成所有滑窗的 GT |

### 决策 ⑥：输出方案与 Loss 函数

#### 输出结构

单网络，二任务输出：

```
输入: [T, 48, 64] 灰度窗口 + fps FiLM 条件
                │
                ▼
        网络主干 (时空编码器)
                │
        ┌───────┴───────┐
        ▼               ▼
  [分割头]          [频率头]
  12×16 二分类      12×16 多分类
  (频闪/非频闪)     (12 类：0=无频闪 + 11 个频率值)
```

| 头 | 输出形状 | 含义 |
|----|---------|------|
| **分割头** | [12, 16] | 每个 grid cell 的频闪概率 (0~1) |
| **频率头** | [12, 16, 12] | 每个 grid cell 的 12 类 logits |

#### Loss 函数

```
L_seg  = FocalLoss(pred_mask, mask_gt)
         └── 二分类，处理正负样本不平衡

L_freq = CrossEntropy(pred_freq, freq_gt) × mask_gt
         └── 只在 GT 频闪区域 (mask_gt=1) 计算
         └── 无频闪区域不参与频率 Loss

L_total = L_seg + λ × L_freq
```

| 参数 | 值 | 说明 |
|------|----|------|
| **Focal Loss γ** | 2 | 经验值，已定 |
| **Focal Loss α** | 待统计数据后确定 | 根据首批标注数据的正负样本比例计算 |
| **λ** | 自适应滑动平均比例 | `λ = avg(L_seg) / avg(L_freq)`, 训练中动态调整 |
| **频率 Loss 范围** | 仅在 mask_gt=1 的 cell 计算 | 无频闪 cell 不参与 |

#### 多频率共存

每个 grid cell 独立预测频率，天然支持不同区域输出不同频率。推理阶段可选做后处理平滑（移除面积 < 2 个 cell 的孤立频闪斑块），但不做强制约束。

### 决策 ⑦：输入值域与数据增强

| 项 | 值 |
|----|----|
| **输入值域** | [0, 1] 归一化（pixel ÷ 255） |
| **空间增强** | 水平翻转 + RandomResize（训练时从 48×64 ~ 96×128 随机缩放再回 48×64） |
| **值域增强** | 暂保留选择空间（待定） |

### 决策 ⑧：评价指标

| 层次 | 指标 | 用途 |
|------|------|------|
| **分割** | mIoU, F1 | 训练调参阶段主要指标 |
| **频率** | Frequency Accuracy, Per-class Accuracy | 模型选型阶段 |
| **联合** | Perfect Cell Rate（分割正确且频率正确的 cell / 所有 GT 频闪 cell） | 最终上线标准 |
| **辅助** | Confusion Matrix（11×11） | 分析模型混淆情况 |

## 6. 关键物理背景：卷帘快门条纹

### 6.1 为什么条纹能解混叠

```
卷帘快门相机: 每帧从上到下逐行曝光
             第 y 行的采样相位比第 y-1 行略晚

设:
  Ts = 一帧的总读取时间 (≈ 1/fps)
  row = 行号 (0 ~ H-1)
  
第 n 帧第 y 行的等效采样时刻:
  t(n, y) = n·Ts + y·Ts/H

频闪信号:  L(t) = A·sin(2π·fs·t)

各行亮度:
  L(n, y) = A·sin(2π·fs·(n·Ts + y·Ts/H))
           = A·sin(2π·(fs·n·Ts + fs·y·Ts/H))
           = A·sin(2π·fs·n·Ts + 2π·(fs/fps)·y/H)

帧间变化:  取决于 term1 = fs·n·Ts    → 时间频率 f
帧内条纹:  取决于 term2 = (fs/fps)·y/H → 空间条纹数 k·y
```

### 6.2 从条纹到真实频率

```
帧内条纹数 = fs / fps = k + f/fps

  其中 k = 整数部分（完整的条纹周期数）
       f = 小数部分（对应表观频率，0 ≤ f < fps）

→ fs = k·fps + f
```

**举例**：

| 场景 | fps | fs | 帧内条纹数 | k | f | 表观 Hz |
|------|-----|----|-----------|----|----|---------|
| 30fps 拍 100Hz | 30 | 100 | 3.33 | 3 | 10 | 10Hz |
| 30fps 拍 800Hz | 30 | 800 | 26.67 | 26 | 20→10 | 10Hz |
| 60fps 拍 200Hz | 60 | 200 | 3.33 | 3 | 20 | 20Hz |
| 120fps 拍 100Hz | 120 | 100 | 0.83 | 0 | 100 | 100Hz |

**关键**：两个映射到同一表观频率的真实频率（如 30fps 下 100Hz 和 800Hz→10Hz），**帧内条纹数不同（3.33 vs 26.67）**，网络可以通过空间条纹密度区分。

| 14 | **Focal Loss α** | 待首批数据统计后确定 |
| 15 | **评价指标** | mIoU/F1 + Frequency Accuracy + Perfect Cell Rate + Confusion Matrix |
| 16 | **预训练策略** | 默认从头训练；保留自监督预训练预案 |
| 17 | **Batch 采样** | 按 fps 分组 batch，每个 step 只处理一种 fps |
| 18 | **窗口融合** | 分割平均→阈值 0.5→频率投票→移除孤立斑块 |
| 19 | **实时性** | 离线分析，不追求实时 |
| 20 | **推理硬件** | 兼容 GPU（RTX 4060 Ti）+ CPU（Win/Mac/Linux） |
| 21 | **部署方案** | Python 训练验证 → TorchScript 导出 → C++ LibTorch 推理 |
| 22 | **Python 验证** | 交付前本地跑推理，查看叠加 MP4 + JSON 报告 |
| 23 | **可视化输出** | 输入视频上叠加分割蒙版 + 频率标注文字，输出 MP4 |
| 24 | **结构化输出** | JSON 逐帧记录检测结果（网格位置、频率） |
| 25 | **数据来源** | 真实拍摄视频，无合成数据 |
| 26 | **硬件** | RTX 4060 Ti 8GB |

## 8. 网络结构方案（v0.2 草案）

### 设计思路

骨干（Backbone）+ 解码器（Decoder）结构：

- **Backbone**: Stem + 4 个 3D ResBlock，时空编码，输出 [192, 12, 16]
- **Decoder**: 两级上采样 + 跳跃连接，逐级恢复空间分辨率到 48×64
- **分割头 + 频率头**：在每个上采样级可以挂输出头，支持灵活的输出精度

### 结构总图

```
                输入: [T, 48, 64]   灰度窗口
                █████████████████
                       │
                       │  fps → FiLM MLP
                       ▼
   ┌─────────────────────────────────────────┐
   │  Stem                                   │
   │  3D Conv(1→32, k=(3,5,5), s=(S,2,2))   │  S: 30=1, 60=2, 120=4, 240=8
   │  BN + ReLU                              │
   │     输出: [T', 24, 32, 32]              │  T'≈45
   └──────────────┬──────────────────────────┘──────┐
                  │                                  │
                  ▼                                  │
   ┌─────────────────────────────────────────┐       │
   │  Block 0  (stride=(1,2,2))               │       │
   │  3D ResBlock(32→64, FiLM inside)         │       │   ← FiLM 在残差路径内部
   │     输出: [T', 12, 16, 64]              │       │
   └──────────────┬──────────────────────────┘──────┐│
                  │                                  ││
                  ▼                                  ││
   ┌─────────────────────────────────────────┐       ││
   │  Block 1  (stride=1)                     │       ││
   │  3D ResBlock(64→128, FiLM inside)        │       ││   ← FiLM 在残差路径内部
   │     输出: [T', 12, 16, 128]             │       ││
   └──────────────┬──────────────────────────┘       ││
                  │                                  ││
                  ▼                                  ││
   ┌─────────────────────────────────────────┐       ││
   │  Block 2  (stride=1)                     │       ││
   │  3D ResBlock(128→160, FiLM inside)       │       ││   ← FiLM 在残差路径内部
   │     输出: [T', 12, 16, 160]             │       ││
   └──────────────┬──────────────────────────┘       ││
                  │                                  ││
                  ▼                                  ││
   ┌─────────────────────────────────────────┐       ││
   │  Block 3  (stride=1)                     │       ││
   │  3D ResBlock(160→192, FiLM inside)       │       ││   ← FiLM 在残差路径内部
   │     输出: [T', 12, 16, 192]             │       ││
   └──────────────┬──────────────────────────┘       ││
                  │                                  ││
                  ▼                                  ││
   ┌──────────────────────────────────────┐          ││
   │  Temporal Conv                        │          ││
   │  3D Conv(k=(T',1,1)) → FiLM → BN     │          ││   ← 合并为单步，加 FiLM
   │     输出: [192, 12, 16]               │          ││
   └──────────────┬───────────────────────┘ ┌────────┘│
                  │                         │         │
                  ▼                         ▼         ▼
   ┌────────────────────────────────────────────────────────┐
   │                     Decoder                            │
   │                                                        │
   │  ┌────────────────────────────────────────────────┐    │
   │  │ Decoder Block 1 (上采样 2× → 24×32)             │    │
   │  │  输入: [192, 12, 16]  ← backbone 最后一层       │    │
   │  │  ↑  skip: Stem 特征 [32, 24, 32]                │    │
   │  │       (先时间池化 → [32, 24, 32])                │    │
   │  │  → Upsample(2×) → [192, 24, 32]                 │    │
   │  │  → Concat + Conv(224→128) → [128, 24, 32]      │    │
   │  └──────────────┬─────────────────────────────────┘    │
   │                 │                                      │
   │  ┌────────────────────────────────────────────────┐    │
   │  │ Decoder Block 2 (上采样 2× → 48×64)             │    │
   │  │  输入: [128, 24, 32]  ← Decoder Block 1         │    │
   │  │  ↑  skip: Block0 特征 [64, 12, 16]              │    │
   │  │       (先时间池化 → Conv1×1降维 → 上采样到 24×32) │    │
   │  │  → Upsample(2×) → [128, 48, 64]                 │    │
   │  │  → Concat + Conv(160→64) → [64, 48, 64]        │    │
   │  └──────────────┬─────────────────────────────────┘    │
   │                 │                                      │
   │                 ▼                                      │
   │  ┌────────────────────────────────────────────────┐    │
   │  │ 输出头                                           │    │
   │  │  分割头: Conv(64→1) → Sigmoid → [48, 64]         │    │
   │  │  频率头: Conv(64→12) → Softmax → [48, 64, 12]    │    │
   │  └────────────────────────────────────────────────┘    │
   └────────────────────────────────────────────────────────┘
```

### 跳跃连接数据处理流程

关键细节：backbone 各层的输出是 3D 的 `[T', C, H, W]`，而 Decoder 接收的是 2D 的 `[C, H, W]`，所以每一条跳跃连接都需要独立的 Temporal Conv。此外在 Stem 的跳跃连接上加一层 3×3 Conv 以平衡两侧特征的成熟度：

```
  Stem:     [T', 32, 24, 32]  ─→ Temporal Conv → [32, 24, 32]
                                   ─→ Conv2D(32→32, k=3×3)  ← 平衡路径长度
                                   ─→ skip 到 Decoder Block 1

  Block 0:  [T', 64, 12, 16]  ─→ Temporal Conv → [64, 12, 16]
                                   ─→ Conv1×1(64→32)
                                   ─→ Upsample(2×) → [32, 24, 32]
                                   ─→ skip 到 Decoder Block 2
```

### 多输出支持（可选）

在 Decoder 中间层和最终层各挂一个输出头，训练时多级监督，推理时选择需要的精度：

```
Decoder Block 1 后:  [128, 24, 32]
  ├── 输出头① → [24, 32] 分割 + [24, 32, 12] 频率  ← 可选输出
  │
Decoder Block 2 后:  [64, 48, 64]
  └── 输出头② → [48, 64] 分割 + [48, 64, 12] 频率  ← 主输出
```

训练时两个头同时算 Loss 并加权求和，推理时直接用 48×64。

### 参数量

| 模块 | 参数量 |
|------|-------|
| Stem | ~4.8K |
| Backbone（4 个 Block） | ~1.1M |
| Temporal Conv（主干 1 + skip 3） | ~80K |
| Decoder（2 个 Block） | ~120K |
| 输出头 | ~800 |
| **合计** | **~1.3M** |

## 9. 运动处理方案

### 9.1 问题背景

数据中有约一半含运动内容（手持拍摄、物体穿过画面等），运动物体会导致卷帘快门条纹在窗口内偏移，干扰频闪识别。

### 9.2 应对策略（分步实施）

```
第一步（初始方案）: 帧差通道辅助
  → 改动最小，快速验证是否能解决大部分运动问题
  → 如果效果不佳，再考虑更复杂方案

第二步（备选方案）: 光流双流网络
  → 如果帧差不够，再加光流分支
```

### 9.3 第一步：帧差通道

在输入中增加一个帧差通道，让网络显式看到运动信息：

```
原输入: [T, 48, 64]         灰度帧

新输入: [T, 2, 48, 64]      灰度帧 + 帧差绝对值
                             其中 frame_diff[t] = |frame[t] - frame[t-1]| / 255
```

帧差通道的特性：
- **值为 0** → 该像素完全静止
- **值较大** → 该像素有运动
- **周期性亮暗变化**（频闪）→ 帧差也会周期性变化，但模式与运动不同

Stem 第一层的输入通道数从 1 改为 2：

```
Stem (v2):
  3D Conv(1→32, ...)    →  3D Conv(2→32, k=(3,5,5), ...)
   ↑ 原版                      ↑ 改动：输入通道 1→2
```

其他部分完全不变。参数量增加不到 1K，显存几乎无影响。

### 9.4 第二步：光流双流（备选）

如果帧差通道不足以分离运动与频闪，升级为双流网络：

```
灰度流: [T, 48, 64] → Stem_gray → Block 0~3_gray
光流场: [T, 2, 48, 64] → Stem_flow → Block 0~3_flow
                                          ↓
                                    在 Temporal Conv 前 concat 融合
                                          ↓
                                    [384, 12, 16] → Decoder
```

代价：
- 参数量翻倍 ~2.6M
- 推理前需要用 RAFT/FlowNet 预计算光流场
- 8GB 显存可能吃紧，需测试

### 9.5 评估方法

```
训练后分别在以下测试集上评估:
  - 静止场景: mIoU / Frequency Accuracy
  - 运动场景: mIoU / Frequency Accuracy

如果运动场景精度 ≥ 静止场景精度 × 0.9 → 帧差方案足够
如果运动场景精度 < 静止场景精度 × 0.7 → 考虑升级到光流双流
```

## 10. 硬件升级预案（8GB → 12GB）

当前设计基于 RTX 4060 Ti 8GB。如果未来升级到 12GB 显存，以下改动可进一步提升性能。

### 10.1 提升输入分辨率（收益最大）

```
当前:      48×64   → 条纹最密时 (30fps×1000Hz):  34% 对比度保留
12GB 升级: 96×128  → 条纹最密时 (30fps×1000Hz):  60% 对比度保留
```

| 指标 | 48×64 | 96×128 | 提升 |
|------|-------|--------|------|
| 每帧像素 | 3K | 12K | 4× |
| 条纹对比度(最坏情况) | 34% | 60% | +26pp |
| 相近频率区分(238vs240Hz) | ⚠️ 困难 | ✅ 容易 | 显著 |
| 训练显存 | ~2-3GB | ~4-5GB | 12GB 够用 |

### 10.2 加宽通道数（增加模型容量）

```
当前:       32 → 64  → 128 → 160 → 192  (~1.3M)
通道 1.5×:  48 → 96  → 192 → 240 → 288  (~3M)
通道 2×:    64 → 128 → 256 → 320 → 384  (~5M)
```

单独加宽度效果有限，因为 48×64 分辨率下的信息量存在上限。

### 10.3 分辨率 + 宽度同时提升（最佳组合）

```
分辨率: 96×128
通道:   48 → 96 → 192 → 240 → 288  (1.5×)
参数量: ~3M
训练显存: ~6-7GB  → 12GB 刚好满足
```

更多像素信息 + 更多参数去利用这些信息，效果最好。

### 10.4 不推荐的改动

| 改动 | 不推荐理由 |
|------|-----------|
| 增加窗口长度 (1.5s→3s) | 2Hz 最低频闪 1.5s 已有 3 个周期，继续加长收益递减，3D conv 计算量翻倍 |
| 单纯加大 batch | 48×64 下 batch 64 已足够，更大 batch 边际收益递减 |

### 10.5 建议升级路径

```
8GB 阶段（先用这个训通 pipeline）:
  48×64, 通道 32→192, ~1.3M, batch 64
  → 先验证模型能收敛、调通训练流程

12GB 阶段（有了再训正式版）:
  96×128, 通道 48→288, ~3M, batch 32
  → 精度应有明显提升
```
